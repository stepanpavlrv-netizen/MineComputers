# MineComputers

Мод для **Minecraft 1.21.1 (NeoForge)** про настоящие компьютеры: детали проектируются на сборочном столе,
собираются в системном блоке, а сквозь стеклянную стенку видно, что установлено внутри.

- **Сборочный стол.** Конструктор комплектующих: ядра и техпроцесс процессора, чипы памяти, плата и охлаждение
  видеокарты, чипсет материнской платы, цвета текстолита, радиаторов и подсветки, гравировка на крышке
  процессора. Характеристики (тепловыделение, объём, отвод тепла) вычисляются из выбранных параметров.
  Окно подстраивается под масштаб интерфейса, все варианты параметра видны сразу (щёлкни нужный; Shift + колесо —
  менять под мышкой), у параметров есть подсказка «?», справа — «что получится» в игровых единицах, внизу —
  материалы: сколько нужно и чего не хватает. **Шаблоны:** заводские детали ур. 1–5 и серверные одним щелчком,
  плюс свои шаблоны (хранятся у игрока в `config/minepc_templates.txt`)
- **8 видов деталей:** материнская плата, процессор, кулер, оперативная память, видеокарта, блок питания,
  жёсткий диск, SSD. У каждой есть 5 заводских уровней
- **Видеоядро в процессоре** (слабое, среднее, сильное): без видеокарты экран выводит оно. Берёт видеопамять
  из оперативной (до 1 ГБ), греется вместе с процессором и быстрее работает с двухканальной памятью;
  сильное — примерно как видеокарта ур. 2. Если стоит видеокарта, работает она
- **Системный блок** со стеклянной боковиной: детали стоят внутри как в реальном ПК (3D-модели в реальных пропорциях)
- **Совместимость:** сокеты, чипсет ограничивает уровень процессора, слоты памяти, M.2 и SATA, каналы памяти,
  мощность блока питания, охлаждение процессора и видеокарты
- **Игровые единицы:** все числа деталей — те, с которыми компьютер работает в игре. Частота процессора в МГц
  (одна команда Lua — один такт: 3,5 МГц = 3,5 млн команд в секунду), память и диски в КБ/МБ, скорость памяти
  в МБ/с, отрисовка в клетках в секунду. Видеочипы — серия VX (VX-110 … VX-590)
- **Реальная производительность:** одна программа работает на одном ядре на его частоте, ядра — сколько программ
  идёт одновременно. Пока процессор холодный, он разгоняется (буст до +30% на тонком техпроцессе), под нагрузкой
  на слабом кулере сбрасывает частоту — по живой температуре. Видеокарта рисует со скоростью своей настоящей
  мощности (чип, частота, видеопамять, охлаждение). Системный блок (Shift + ПКМ) считает сборку целиком:
  частоту под нагрузкой, нехватку памяти, узкие места и итоговую оценку (заводская сборка ур. 3 ≈ 1000 очков)

- **Компьютеры работают:** Lua (движок Cobalt, как в CC: Tweaked), командная строка, редактор кода с подсветкой,
  файлы на дисках, дискетах и флешках. Скорость процессора — настоящий лимит команд в секунду
- **Периферия:** монитор (картинка прямо на блоке), клавиатура, дисковод; дискеты и флешки переносят файлы
  между компьютерами. Мониторы одного направления, поставленные прямоугольником (до 8×8 блоков), становятся
  одним большим экраном
- **Экран:** Unicode (кириллица, псевдографика, символы), цвет до 24 бит (любой RGB — на видеокарте ур. 5),
  до 320×100 символов на стене мониторов. Работает мышь: клики, перетаскивание, колесо
- **Характеристики — настоящие лимиты** (подробнее — раздел «Железо и лимиты» ниже): скорость процессора,
  ядра для параллельных процессов, память для программ, скорость отрисовки и видеопамять, скорость накопителей
- **Загрузка файлов:** перетащи файл со своего компьютера в окно экрана — он появится в корне системного диска
- **Совместимость с OpenOS (OpenComputers):** `require`, `component`, `event`, `term`, `filesystem`, `io`,
  `serialization`, `unicode`, `computer`, `shell`, `keyboard`. Многие программы для OpenComputers запускаются
  без изменений — например, графическая оболочка Okna OS (нужна видеокарта ур. 4 для экрана 160×50)

> Статус: активная разработка. Сделано: сеть (кабели, коммутаторы, Wi-Fi, радио, розетки, бирки, тестер, точки
> доступа и карта покрытия, радиовышки с антеннами, прямая видимость и погода) и серверная (стойка, сетевые модули
> и шина, серверные детали, RAID, BMC). Дальше по плану — Python-контроллеры.

## Как собрать работающий компьютер

1. Поставь **системный блок**, открой его (ПКМ) и разложи детали по слотам: материнская плата, процессор, кулер,
   память, блок питания и хотя бы один накопитель (HDD или SSD). Видеокарта нужна для цвета и большого экрана.
   Наведи мышь на пустой слот — подсказка скажет, что туда ставится
2. Вплотную к системному блоку поставь **монитор**, рядом с монитором — **клавиатуру**
3. В окне системного блока нажми **кнопку питания** (справа вверху). На экране состояния — сводка, питание,
   нагрев и накопители (вкладки); наведи мышь на экран — подробный отчёт о сборке
4. ПКМ по монитору (или клавиатуре) — экран крупно. Введи `help`

Полезное в командной строке:

| Команда | Что делает |
|---|---|
| `edit hello.lua` | редактор: Ctrl+S — сохранить, Ctrl+Q — выйти |
| `hello` | запустить программу hello.lua |
| `lua` | интерактивный Lua |
| `ls`, `cd`, `mkdir`, `cp`, `mv`, `rm`, `cat` | работа с файлами |
| `drives` | накопители и свободное место (`/disk` — дискета, `/usb` — флешка) |
| `info` | железо и скорость компьютера |
| `sh` | вложенная командная строка (`exit` — вернуться) |
| `ps`, `kill <номер>` | процессы на ядрах процессора |

Ctrl+T — прервать программу, Ctrl+V — вставить текст из буфера обмена, Esc — закрыть экран.
Чтобы перенести программу со своего компьютера, перетащи файл в окно экрана (до 4 МБ).
Файлы накопителей лежат в папке мира: `saves/<мир>/minepc/drives/<номер>/` — их можно править и снаружи игры.

## Корпуса, мониторы и клавиатуры

Системный блок бывает в 14 обликах — внутри у всех одно и то же, меняется вид и оформление окна корпуса.
Рецепт: обычный системный блок + материал (по-новому скрафтить обратно — положить корпус в верстак один).

| Корпус | Добавить к системному блоку | Окно |
|---|---|---|
| Ретро-тауэр / настольный ретро / домашний 80-х (со встроенной клавиатурой) | берёзовые доски / берёзовая плита / клавиатура | ретро |
| Офисный мини-тауэр / мини-ПК / рабочая станция | чёрный краситель / железный слиток / железная решётка | офис |
| Моноблок (экран и клавиатура) | монитор | офис |
| Игровой / игровой белый / игровой куб | стеклянная панель / белая стеклянная панель / осколок аметиста | игровое |
| Шкаф управления / пульт (наклонный экран, кнопки) | железный блок / настенная панель | промышленное |
| Серверная стойка / стойка с консолью | цепь / терминал | серверное |

У корпусов со встроенным экраном ПКМ открывает экран, Shift + ПКМ — окно корпуса.

### Модульная серверная стойка

**Серверная стойка** (железные слитки по краям + железная решётка в центре) — блок на 4 места по 1U, снизу вверх.
В место ставится **модуль сервера** (2 железных слитка, редстоун, сетевой кабель) или **модуль консоли**
(железный слиток, стеклянная панель, клавиатура, редстоун): ПКМ модулем по нужной высоте стойки.

- **Каждый сервер — отдельный компьютер:** свои детали, имя и адрес в сети, свой экран, окно и звук.
  Гнёзда сзади стойки — по одному на каждое место, на высоте модуля.
- **ПКМ** по модулю — выдвинуть его (у сервера снимается крышка, видно детали). **ПКМ** по выдвинутому —
  окно сервера (в нём кнопка «Терминал») или экран консоли. **Shift + ПКМ** — задвинуть. Shift + ПКМ по задвинутому
  выключенному модулю — вынуть его целиком: сервер уходит в предмет вместе с деталями и файлами.
- Выдвинут может быть только один модуль стойки; перед стойкой должно быть свободное место.
  Детали ставятся в выдвинутый сервер ПКМ деталью.
- **Ряд стоек**: стойки друг на друге и бок о бок (смотрящие в одну сторону) работают вместе — у них общая шина
  и общая консоль.
- **Консоль** — экран и клавиатура на весь ряд стоек: выбираешь сервер из списка и работаешь в его терминале,
  сверху — вкладки остальных серверов ряда; у каждого сервера в списке своя кнопка питания. Серверы ряда
  с консолью считаются компьютерами с клавиатурой.

### Сеть в стойке

| Модуль | Высота | Что делает |
|---|---|---|
| **Коммутатор** | 1U | Шина стойки: все серверы ряда подключены к нему без шнуров. Спереди 3 медных гнезда и SFP для оптики — наружу |
| **Патч-панель** | 1U | Сзади — кабели здания (2 медных и оптика), они выходят на шину |
| **Роутер** | 2U | Соединяет VLAN шины между собой (+1 переход); спереди — порты WAN наружу |
| **ИБП** | 2U | Батареи и лампы заряда (пока питание условное — для вида) |
| **Заглушка** | 1U | Закрывает пустое место |

- Шина работает, если в ряду есть хотя бы один модуль коммутатора. ПКМ по коммутатору, роутеру или патч-панели —
  окно портов шины: каждому серверу можно выключить порт или задать VLAN (цвет). То же — программой `switch`.
- Гнёзда серверов сзади остаются: сервер можно подключить и проводом напрямую.
- Отдельные блоки «Стоечный коммутатор» и «Патч-панель» больше не крафтятся: уже поставленные работают как раньше,
  а в верстаке такой блок превращается в модуль.

### Серверные детали

Делаются на том же сборочном столе — у детали появились серверные варианты (или одним щелчком: шаблон «Сервер»).

| Деталь | Обычная | Серверная |
|---|---|---|
| Плата («Тип платы») | один сокет, 2–4 слота памяти, 1–4 канала | два сокета MS-S, 8–16 слотов, 4–8 каналов, 2 × 10 Гбит/с |
| Процессор (сокет MS-S) | 1–32 ядра, видеоядро по желанию | 16–128 ядер, без видеоядра; два одинаковых на плате — ядра складываются |
| Память («Тип») | обычная | ECC: только в серверную плату, а обычная в серверную не встанет |
| Блок питания | один | два: каждый должен один тянуть весь сервер |
| Охлаждение | кулер | стена вентиляторов (260 Вт отвода на процессор); в 1U кулер не влезает |

- Серверная плата выглядит по-своему: два больших сокета MS-S в рамках, память рядами вдоль потока воздуха,
  радиаторы питания за сокетами, сзади две клетки SFP+, порт и чип BMC. В выдвинутом модуле стойки видны все её слоты.
- Серверная плата и второй блок питания ставятся только в **серверное шасси**: модуль стойки или серверный корпус.
  У него своё окно: память в три ряда вокруг двух сокетов, справа два блока питания и четыре отсека дисков.
- **Пока сервер работает**, плату, процессоры, память, видеокарту и M.2 не вынуть — сначала выключить.
  **Диски в отсеках меняются на ходу:** программа получает событие `disk_eject` / `disk`, остальные диски работают;
  вынули системный — сервер падает. **Блок питания** вынимается на ходу, если второй тянет нагрузку (событие
  `power_supply` с числом блоков); с одним блоком лампа питания на модуле и в окне жёлтая.
- Сколько ядер реально работает одновременно, ограничивает настройка сервера `maxCores`.

### Сервер 2U, отсеки дисков и RAID

- **Модуль сервера 2U** (4 железных слитка, редстоун, сетевой кабель) занимает два места стойки: 8 отсеков дисков
  в два ряда и вентиляторы мощнее. У модуля 1U — 4 отсека.
- У сервера **отсеки универсальные**: в любой встаёт жёсткий диск или SATA SSD, все меняются на ходу.
- **Износ дисков**: работающий диск изнашивается (по умолчанию — только у серверов; настройки `diskWear`
  и `diskLifeHours`). С 90% диск **просит замены** — его лампа горит жёлтым, в журнале BMC запись, программе
  событие `disk_warning`. На 100% диск **отказывает** (красная лампа, событие `disk_failed`): отдельный диск
  со всем содержимым становится недоступен. Износ виден в подсказке диска, во вкладке «Диски» окна и в `raid`.
- **RAID** — контроллер на серверной плате. `raid create mirror|stripe|raid5` собирает массив из всех дисков
  в отсеках (их данные стираются) и перезагружает сервер; массив виден как один диск (`/` или `/data`).

| Массив | Объём | Скорость | Переживёт |
|---|---|---|---|
| `stripe` (RAID 0) | все диски вместе | все вместе | ни одного отказа |
| `mirror` (RAID 1) | один диск | один диск | все диски, кроме одного |
| `raid5` (от 3 дисков) | все, кроме одного | все, кроме одного | один отказ |

- Диск массива отказал или его вынули — массив **работает без резерва** (`stripe` — разваливается). Вставили
  новый диск — массив **восстанавливается** на него (лампа отсека мигает, 10 с – 1 мин), потом снова исправен.
  Вынутый диск массива можно вернуть обратно. `raid` — состояние массива и дисков, `raid delete` — разобрать.
  Lua: `bios.raid()`, `bios.raidCreate(уровень)`, `bios.raidDelete()`, событие `raid` (ok / degraded / rebuilding / failed).

### BMC: сервер под присмотром

На серверной плате есть **BMC** — маленький отдельный компьютер. Он работает от дежурного питания (нужен хоть один
блок питания), даже если сервер выключен или упал, и отвечает по проводной сети через гнездо модуля.

- С любого компьютера сети: `bmc <сервер> status` — питание и время работы, процессоры и температура, вентиляторы,
  блоки питания, диски и массив RAID, потребление; `sensors`; `log [N|clear]` — журнал событий; `screen` — что сейчас
  на экране сервера; **`console` — экран и клавиатура сервера по сети** (Ctrl+T — выйти); `power on|off|reset`;
  `password <новый>`. Сервер — по имени, адресу или адресу BMC.
- Пароль спрашивается при вызове (или `bmc -p пароль <сервер> …`). **По умолчанию — `admin`**: смените на самом
  сервере командой `bmc password <новый>`. Просто `bmc` на сервере — адрес своего BMC и состояние пароля.
- В журнал попадает: включение и выключение (кнопкой, с консоли или по BMC), неудачный запуск, блоки питания
  и диски, вынутые и вставленные (в том числе у выключенного сервера), перегрев процессора, неверный пароль.
- Lua: `net.bmc(сервер, пароль, команда [, аргумент])` → `ok, сообщение, данные` (таблица: `power`, `temp`, `rpm`,
  `psu`, `disks`, `watts`…), `net.bmcInfo()`, `net.bmcPassword(новый)`.
- Консоль стойки: у каждого сервера в списке своя кнопка питания.

Мониторы (рецепт: монитор + материал): **плоский** (складывается в стену до 8×8), **широкоформатный** и **изогнутый**
в два блока (два монитора → широкий, широкий + красный краситель → изогнутый; ставятся сразу двумя половинами,
нужно свободное место справа), **кинескоп**, **ламповый телевизор**,
**терминал** (клавиатура встроена), **настенная панель**, **блочные** — тёмный, белый и ретро: целые блоки, которые
стыкуются без швов, рамка только по краю всей стены.

**Покраска:** ПКМ красителем по корпусу-варианту или монитору красит его корпус (лампочки, экран и детали остаются
как были), ПКМ ведром воды — смыть краску. Не красятся обычный системный блок и ламповый телевизор.

Клавиатура: рядом с монитором или корпусом; ПКМ клавиатурой по плоскому монитору — она встаёт в тот же блок
(Shift + ПКМ пустой рукой — вынуть); ПКМ клавиатурой по боку другого монитора — вешается на него полкой.
**Клавиатурная стойка** — клавиатура на подставке (клавиатура + железная решётка).

## Сеть

У каждой материнской платы есть сетевой порт: 100 Мбит/с (ур. 1), 1 Гбит/с (ур. 2–3), 2,5 Гбит/с (ур. 4), 10 Гбит/с (ур. 5);
в игре скорость делится на 800 → байт/с (1 Гбит/с = 1,25 МБ/с). Схема сети хранится в данных мира, поэтому связь идёт
и через незагруженные чанки (компьютеры на концах, конечно, должны работать).

**Провода**
- **Сетевой кабель** (8 шт.: нитки + медь + нитки) — провод толщиной в пиксель, лежит на гранях блоков (пол, стена,
  потолок, верх блока). **Прокладывается щелчками**: ПКМ мотком по гнезду (или по полу, стене) — начало; дальше каждый
  ПКМ — точка излома, ровно в тот пиксель, куда щёлкнул; ПКМ по гнезду другого устройства — конец, и провод ложится
  целиком. Ещё раз по последней точке — закончить со свободным концом; Shift + ПКМ — шаг назад (последняя точка).
  Между точками путь находится сам — по полу, вверх по стене через внутренний угол, через верх стены и вниз по другой
  стороне, по потолку, — с наименьшим числом поворотов. Пока ставишь точки, за прицелом идёт голубой призрак, у прицела —
  сколько уйдёт кабеля и в какой порт воткнётся; где провод лечь не может, — красная рамка и причина («нет опоры»,
  «все линии заняты», «пути нет»). С мотком в руке у свободных гнёзд вокруг — зелёные рамки.
  Провода на одной грани не налезают друг на друга (до 8 на грани), пересекаться под прямым углом могут.
  Краситель во второй руке — цвет нового провода; ПКМ красителем по проводу — перекрасить (разные цвета — разные сети).
  Ломается по одному проводу — тот, на который смотришь. Медный отрезок без коммутатора — не длиннее 100 блоков.
  Старые провода (до 0.31) переводятся сами и работают как раньше.
- **Гнёзда**: у устройств настоящие гнёзда — у настольного коммутатора 6 спереди, у стоечного два ряда по 6, у
  патч-панели 6 спереди и 6 сзади, у роутера сзади WAN и 4 LAN, у компьютера — один сетевой разъём на задней
  панели (сбоку и спереди кабель не воткнуть; старые провода, воткнутые сбоку, при загрузке мира отсоединяются).
  Конец провода у устройства сам втыкается в ближайшее свободное гнездо (провод, идущий мимо, не втыкается).
  Порт 1 — левый, если смотреть на гнёзда.
- **От гнезда до гнезда**: ПКМ по гнезду одного устройства и сразу по гнезду другого (без точек излома) — путь
  находится сам, тем же поиском по полу, стенам и потолку.
- **Моток с длиной**: полоска под значком — сколько метров осталось (полный моток — 64 м), 1 м на блок.
- **Кусачки** (ножницы + медь + красный краситель): ПКМ по проводу — снять его, Shift + ПКМ — весь жгут в блоке,
  по кронштейну — его воздушные линии; кабель возвращается в инвентарь.
- **Воздушная линия**: кронштейны (железо + кварц → 4) на пол, стену или потолок; ПКМ мотком по одному, потом сразу по другому —
  кабель натягивается с провисом, до 24 блоков пролёт. В изолятор кронштейна втыкаются провода снизу и с боков.
  Висячие провода (воздушные линии и патч-корды) не проходят сквозь блоки: если на пути блок, провод не натянется
  (призрак станет красным и обведёт мешающий блок); блок поперёк висящего провода не поставить, а если он оказался
  там иначе (поршень, дерево, песок) — провод обрывается и падает.
- **Подсказки монтажника**: взгляд на гнездо — порт, есть ли связь, куда ведёт кабель и сколько в нём блоков, VLAN;
  с мотком или кусачками взгляд на провод — весь его отрезок подсвечен, «47 / 100 блоков» и куда воткнуты концы.
  Лампочки над гнёздами коммутаторов горят, если в гнездо воткнут провод, и мигают, когда идут сообщения.
- **Оптоволокно** (нитки + стеклянные панели + кварц): жёлтое, 10 Гбит/с, до 2000 блоков без коммутатора,
  втыкается только в стоечный коммутатор (и в патч-панель).
- **Спрятать кабель**: ПКМ по кабелю обычным блоком (камень, доски…) — кабель внутри, снаружи блок. Сломал — сначала снимается блок.
- **Кабельный лоток**: до 8 проводов (по одному каждого цвета), ставится где угодно — по стене вверх, под потолком.
  ПКМ мотком — положить провод (цвета по очереди, краситель во второй руке — свой), красителем — перекрасить последний.
  Соединяется с соседними лотками и с проводами на полу того же цвета.
- **Патч-корд**: короткий провод до 4 блоков между устройствами. ПКМ по одному, затем по другому; Shift+ПКМ — снять.
- **Патч-панель** (для стойки): гнездо спереди соединено с гнездом сзади на той же дорожке и с патч-кордом в этом гнезде.
  Пассивная — без задержки.
- **Сетевая розетка** (кварц + кабель + железный самородок → 2): белая пластина на стене, полу или потолке с двумя
  линиями A и B. Кабель здания подходит к ней по стене снизу, сверху или сбоку (у каждой кромки по гнезду на линию),
  компьютер — коротким кабелем или патч-кордом в гнездо спереди. Пассивная, как патч-панель. **Две розетки на
  разных сторонах одной стены** (одна напротив другой) соединены сквозь неё: A с A, B с B — кабель проходит сквозь
  стену, не ломая её.
- **Бирки**: переименуй моток (или патч-корд) на наковальне — у вилок проводов из него появятся белые бирки, а имя
  будет видно в подсказке порта, в окне коммутатора (белая плашка) и в программе `switch`. Снятый провод возвращается
  в инвентарь с тем же именем.
- **Кабельный тестер** (кабель + 2 редстоуна + стеклянная панель + жёлтый краситель): ПКМ по гнезду устройства
  или по проводу — прозвонка. Весь кабель на 10 секунд подсвечивается оранжевым **сквозь стены** (и патч-корды, и путь
  через патч-панели и розетки — голубые рамки), устройство на другом конце мигает зелёным, а место, где провод
  обрывается, — красным. Пока тестер в руке, в углу экрана его экранчик: длина и предел, скорость, есть ли обрыв,
  бирка и что на концах (тот же результат — в подсказке к тестеру).

**Устройства**
- **Коммутатор** (6 гнёзд спереди, 1 Гбит/с) и **стоечный** (2 × 6 спереди, медь и оптика, 10 Гбит/с,
  соседние стоечные работают как один). +1 тик задержки. ПКМ — окно портов: включить/выключить порт и **VLAN** (цвет):
  порты разных цветов друг друга не слышат, без цвета — общая сеть.
- **Wi-Fi роутер**: ПКМ — имя сети, пароль (пусто — открытая, иначе от 8 знаков), радиус до 48 блоков, кто подключён.
  Кабель — сзади или сбоку, роутер соединяет Wi-Fi с проводной сетью.
- **Потолочная точка доступа** (роутер + кварц + светопыль): белая «шайба» с синим кольцом, вешается только под потолок.
  Окно то же, что у роутера, но радиус до 24 блоков (по умолчанию 16), зато каждая стена отнимает у сигнала только
  1 блок вместо 3. Кабель подходит к ней по потолку — гнёзда с четырёх сторон.
- **Карта покрытия**: с роутером, точкой доступа или Wi-Fi адаптером в руке на полу вокруг видны точки — зелёные
  (сигнал сильный), жёлтые (слабее), красные (край зоны); вверху экрана — сигнал там, где стоишь. С адаптером
  считается по его дальности, с роутером в руке — по радиусу роутеров рядом.
- **USB Wi-Fi адаптер** в USB-порт корпуса: 54 Мбит/с и 16 блоков, 300 и 32, 1200 и 48. Каждая сплошная стена до роутера
  отнимает 3 блока; чем дальше, тем слабее сигнал и ниже скорость. Подключение — программа `wifi`.
- **Радиомодем**: связь на 250 блоков, каждая **секция мачты** над ним (мачта на крышу) — ещё 250 (до 1000), но медленно —
  около 2 КБ/с. Канал — цвет (покрасьте оба модема одинаково). ПКМ — вышка, антенны, дальность, громоотвод и с кем
  есть связь: через что, скорость, есть ли прямая видимость.
- **Радиовышка** (железо + решётки + красный краситель → 4 секции): решётчатая, до 32 секций. Ставится на землю,
  дальше — ПКМ секцией по вышке, и новая секция встаёт на макушку. Вышка сама сужается кверху (внизу 3×3, наверху 1×1),
  окрашена красно-белыми полосами по 2 секции (серым красителем — оцинкованная, красным — обратно), на макушке
  и каждые 6 секций — красные огни, ночью и в грозу мигают. Внутри вышки можно лезть вверх, как по лестнице; по центру
  идёт чёрный фидер. Сломал секцию — всё, что выше, рушится. **Радиомодем ставится рядом с нижней секцией (до 2 блоков — снаружи широкой вышки).**

  | Высота вышки | 4 | 8 | 12 | 20 | 32 |
  |---|---|---|---|---|---|
  | Дальность штыря и секторов, блоков | 300 | 600 | 1000 | 1800 | 3000 |

  - **Штыревая антенна** на макушке — во все стороны.
  - **Секторная антенна** на боку секции — на свою четверть круга (куда смотрит); если и у другой вышки в её
    сторону сектор — в 4 раза быстрее штыря.
  - **Антенна-тарелка** на боку секции — только на тарелку другой вышки, повёрнутую навстречу: вдвое дальше
    и в 16 раз быстрее (около 32 КБ/с). Наводится поворотом: тарелка смотрит на свою четверть круга.
  - Вышка без антенн — работает только антенна шкафа (250 блоков).
- **Прямая видимость**: между антеннами проверяется рельеф по прямой. Холм или постройка выше линии — связь
  в 4 раза медленнее (настройка `radioLineOfSight`: 0 — не проверять, 1 — замедлять, 2 — рвать связь). Высота вышки
  помогает: линия идёт от макушки. Где чанк не загружен, берётся рельеф из генератора мира (чанки не грузятся).
- **Погода** (настройка `radioWeather`): в дождь дальность радио на 15% меньше; в грозу молния бьёт в вышки —
  **громоотвод** (обычный, из игры) на макушке, над штырём или вместо него, уводит разряд в землю, а без него модем
  выбит на минуту.

**Программы**: `ip`, `hostname имя`, `peers`, `ping имя [раз]` (настоящее время туда и обратно), `chat [канал]`,
`wifi` / `wifi scan` / `wifi connect сеть [пароль]`, `send имя файл` и `recv` (передача файлов), `switch` (коммутаторы,
порты, VLAN).

**Lua**: `net.open(порт)`, `net.send(имя_или_адрес, порт, ...)`, `net.broadcast(порт, ...)`, событие `net_message`
(отправитель, порт, переходов, данные...), `net.ping(имя)` → событие `net_pong`, `net.peers()`, `net.address()`,
`net.hostname([имя])`, `net.speed()`, `net.wifi.scan/connect/status/disconnect`, `switch.list()`, `switch.ports(id)`,
`switch.set(id, порт, вкл, цвет)` (у порта есть `label` — бирка кабеля), `data.encrypt(данные, ключ [, iv])` / `data.decrypt` (AES-128). Сообщение — до 8 КБ.
Для OpenOS порт виден как `component.modem` (событие `modem_message`). В окне корпуса — вкладка «Сеть».

## Железо и лимиты

Каждая характеристика работает по-настоящему — и всё щедрее, чем в OpenComputers:

| Деталь | Что ограничивает | MineComputers | OpenComputers |
|---|---|---|---|
| Процессор | частота ядра (команд Lua в секунду) | 0,5–8 МГц и буст до +30%: ур. 1 — 0,5 МГц, ур. 3 — 3,5 (буст 3,85), ур. 5 — 7 (буст 9,1) | без счёта команд |
| Процессор | ядра = параллельные процессы | столько, сколько ядер (до 8) | один поток |
| Память | сколько данных держат программы | «ГБ» планок = МБ в игре (до десятков МБ) | до 2–4 МБ |
| Видеокарта | экран и цвета | до 320×100, до 24 бит | до 160×50, 8 бит |
| Видеокарта | скорость отрисовки | 20–640 тыс. клеток/с по настоящей мощности, заливка и копирование в 8 раз дешевле | лимит вызовов за тик |
| Видеокарта | видеопамять (буферы, `bitblt`) | от 32 тыс. клеток, растёт с объёмом видеопамяти | до 3 экранов |
| Накопитель | объём и скорость | жёсткий диск ≈ 1–2 МБ/с, NVMe до 70 МБ/с, дискета 128 КБ/с | без скорости |
| Накопитель | время загрузки системы | SSD — доли секунды, жёсткий диск — несколько секунд | нет |

- **Память.** Не хватает — в программе возникает ошибка «Недостаточно памяти» (её можно поймать `pcall`).
  `computer.freeMemory()`, `collectgarbage("count")` показывают настоящие числа
- **Встроенные функции** (`string.rep`, `table.concat`, `string.upper`, `data.sha256`...) работают на Java
  и стоят команд по объёму данных — всё равно в разы быстрее, чем то же самое циклом на Lua
- **Библиотека `data`** (как карта данных OpenComputers, но встроена): `crc32`, `md5`, `sha256`,
  `encode64`/`decode64`, `deflate`/`inflate`, `random`, `toHex`, `encrypt`/`decrypt`. Доступна и как `component.data`
- **Экран** после включения 160×50; `term.setResolution(term.maxResolution())` разворачивает на всю стену.
  Стена мониторов: 1 блок — 160×50, каждый блок вширь +80 столбцов, каждый ряд +25 строк (3×3 = 320×100)
- **Видеопамять** — как в OpenComputers 1.8: `gpu.allocateBuffer`, `gpu.setActiveBuffer`, `gpu.bitblt`...
  Рисование в буфер бесплатное, на экран — по скорости видеокарты

### Процессы на ядрах

```lua
local cores = require("cores")
local pid = cores.spawn("worker.lua", 1, 1000)   -- запустить программу на свободном ядре
cores.send(pid, "задание", { from = 1, to = 1000 })  -- числа, строки, таблицы (копируются)
local from, result = cores.receive(10)           -- ждать ответ до 10 секунд
local ok, err = cores.wait(pid)                  -- дождаться завершения
```

У каждого процесса свои переменные (общих таблиц нет — только сообщения), а экран, файлы и память общие.
Процессов больше, чем ядер, — они делят ядра. В командной строке: `ps` — список процессов, `kill <номер>`.

### Кадровый буфер и игры

Видеокарта умеет рисовать «точками»: `gpu.canvas(w, h)` — картинка до ширины экрана × двойной высоты,
в которую быстрые команды на Java рисуют заливки, градиенты, столбцы стен с текстурой, полосы пола и
спрайты с прозрачностью и глубиной; `present()` одной командой выводит её на экран полублоками.
Текстуры — `gpu.newTexture(w, h, точки)`. Пример — программа `bunker`, 3D-стрелялка в духе Doom:
на топовом компьютере держит 30 кадров в секунду на экране 320×196 точек (`bunker demo` играет сама,
`bunker bench` замеряет скорость).

Время компьютера идёт по настоящим часам: таймеры и `os.sleep` точны до миллисекунды, нажатия
обрабатываются сразу, экран уходит игроку, как только изменился (до 60 раз в секунду; на сервере —
с ограничением трафика, настройки `screenFps` и `screenKbPerSecond`). Когда игра на паузе, время стоит.

### Звук

Работающий компьютер гудит вентиляторами (громче и выше под нагрузкой и при нагреве) и жёстким диском,
диск и дисковод трещат при чтении и записи, клавиатура стучит, детали щёлкают защёлками, патч-корды —
разъёмами, коммутаторы тихо щёлкают, а радиомачты трещат, когда по сети идут сообщения.
При включении плата пищит: один короткий — всё хорошо, длинный и два коротких — нет видеокарты,
три длинных — нет памяти.

Программы звучат через пищалку и звуковой чип платы (2–8 каналов, больше на платах дороже):

```lua
computer.beep(440, 0.3)              -- пищалка: частота и длительность; или узор ".-."
sound.play(1, "C5", 0.2, 0.8, "square", "C6")   -- нота сразу: канал, частота, секунды, громкость, волна, до частоты
sound.setWave(1, sound.modes.sine)   -- очередь как у звуковой карты Computronics:
sound.setFrequency(1, 440) sound.open(1) sound.delay(250) sound.close(1)
sound.process()                      -- отправить очередь (до 5 с за раз, вперёд — до 6 с)
```

Сервер отправляет игрокам рядом не звук, а короткие команды; звук собирает синтезатор у игрока, поэтому
трафика почти нет. Программа `music` играет мелодии (`music korobeiniki`, `music ode`, `music elise`
или свой файл с нотами `E5/4 C#5/8. R/2`), `bunker` озвучен. Громкость каждой группы звуков игрок
настраивает в `config/minepc-client.toml`; звук программ ещё и ползунком «Музыкальные блоки».
Откуда взяты записи — `tools/sounds/CREDITS.md`, сами звуки собирает `tools/sounds/make_sounds.py`.

### BIOS и нагрузка

При включении — экран самотеста. **Del** (или F2) — настройки BIOS, **F12** — меню выбора диска для загрузки.
Платы 1–3 уровня — классический синий BIOS (клавиатура), платы 4–5 — графический UEFI (можно мышью).

| Вкладка | Что там |
|---|---|
| Main | процессор, память, видеокарта, серийный номер платы, время в мире |
| Advanced | сколько ядер включено, встроенная сеть, USB-порты, Wi-Fi, быстрая загрузка |
| Boot | порядок загрузки: NVMe, SATA, HDD, флешка, дискета |
| Security | пароль на вход в BIOS и пароль при включении |
| Power | что делать после загрузки мира, включение сигналом красного камня |
| Monitor | температура процессора и видеокарты, вентилятор, напряжения, потребление |

Настройки хранятся **в самой материнской плате** (как батарейка CMOS): переставил плату в другой корпус —
настройки переехали. F10 — сохранить и перезагрузиться, F5 — по умолчанию. Из программ: `bios.get()`,
`bios.set{...}`, `bios.info()`.

`computer.stats()` — настоящая нагрузка, как в диспетчере задач Windows: каждое ядро, каждый процесс (ЦП и память),
чтение и запись каждого диска, видеокарта, сеть, температуры (растут под нагрузкой, зависят от охлаждения),
вентилятор, потребление. В командной строке — программа `top`; в Okna OS — диспетчер задач с вкладками
«Процессы», «Производительность» (графики за 60 секунд, по ядрам), «Автозагрузка».

### Настройки сервера

`saves/<мир>/serverconfig/minepc-server.toml` (на сервере — `world/serverconfig/`): множители скорости процессоров
(отдельно для сервера и одиночной игры), памяти, видеокарт и накопителей, потолок памяти на компьютер, сколько
ядер и процессов можно, сколько потоков сервера отдать компьютерам, включено ли время загрузки. Компьютеры
работают в своих потоках: даже если их много, игра не тормозит — программы просто получают меньше времени.

## Как запустить у себя

1. **Java 21** — [Temurin 21 (LTS)](https://adoptium.net/), при установке включить «Set JAVA_HOME» и «Add to PATH».
   Проверка: `java -version` в командной строке должна показать 21
2. **IntelliJ IDEA** — [jetbrains.com/idea](https://www.jetbrains.com/idea/download/), бесплатной версии достаточно.
   Полезен плагин **Minecraft Development** (Settings → Plugins)
3. Склонировать репозиторий **в папку без русских букв и пробелов**, например `D:\Mods\MineComputers`
4. В IntelliJ: **File → Open** → папка репозитория → **Trust Project**. Первая загрузка (Gradle sync) занимает
   5–20 минут: скачивается сам Minecraft
5. Запуск игры: в терминале IntelliJ (`Alt+F12`)
   ```
   .\gradlew runClient
   ```
   или вкладка **Gradle** (слон справа) → **Tasks → mod development → runClient**

В игре всё лежит во вкладке творческого режима **MineComputers**.

### Если что-то не запускается

- **`Failed to run Gradle Worker Daemon`** — почти всегда русские буквы в имени пользователя Windows.
  Создай папку `D:\gradle-home` и переменную среды пользователя `GRADLE_USER_HOME = D:\gradle-home`,
  перезапусти IntelliJ, выполни `.\gradlew --stop`, затем снова `.\gradlew runClient`
- **Ошибка 504 при скачивании Gradle** — скачай `gradle-9.2.1-bin.zip` через браузер
  (`https://services.gradle.org/distributions/gradle-9.2.1-bin.zip`), положи, например, в `D:\Mods\`
  и в `gradle/wrapper/gradle-wrapper.properties` поменяй строку на
  `distributionUrl=file\:///D:/Mods/gradle-9.2.1-bin.zip`.
  Чтобы git не пытался отправить это изменение в репозиторий:
  ```
  git update-index --skip-worktree gradle/wrapper/gradle-wrapper.properties
  ```
- **`Unknown command-line option '-b'`** — запускался сам файл `build.gradle`. Запускай задачу `runClient`, как выше
- Если в меню **New** нет пунктов **Package** и **Java Class** — открыта не та папка (нужна та, где лежит
  `build.gradle`) или ещё не закончилась загрузка Gradle

## Как устроен код

```
src/main/java/com/strikerr212/minepc/
├── MineComputers.java          главный класс, регистрирует всё остальное
├── hardware/
│   ├── spec/                   ★ СЕРДЦЕ МОДА: параметры и расчёты деталей
│   │   ├── PartSpec.java         базовый класс спецификации (уровень, стоимость, вид)
│   │   ├── CpuSpec.java ...      по классу на каждый вид детали
│   │   ├── Param.java            один настраиваемый параметр
│   │   ├── Palette.java          палитры цветов
│   │   ├── PartDesign.java       "чертёж", который хранится внутри предмета
│   │   └── Specs.java            все спецификации в одном месте
│   ├── HardwarePresets.java    заводские детали 5 уровней + примеры самосборных
│   └── *Data.java              вычисленные характеристики (паспорт детали)
├── item/                       предметы-детали (тонкая обёртка над спецификацией)
├── block/                      системный блок и сборочный стол
├── computer/                   ★ КОМПЬЮТЕР без Minecraft: Lua, экран, файлы, лимит команд
│   ├── Computer.java             включение, события, порции команд за тик
│   ├── LuaMachine.java           виртуальная машина Lua (Cobalt) и счётчик команд
│   ├── LuaApis.java              term, fs, os, computer — функции для программ
│   ├── Terminal.java             текстовый экран
│   └── fs/                       файловая система: диски в папке мира, ПЗУ
├── menu/                       окна: сборочный стол, системный блок
├── network/                    пакет с надписью (клиент → сервер)
├── client/                     всё, что только рисует: экран стола, рендер деталей в корпусе, цвета
└── registry/                   регистрация блоков, предметов, меню, вкладки
```

**Программы компьютера** (BIOS, командная строка, редактор, команды) — это Lua-файлы в
`src/main/resources/data/minepc/computer/`. После добавления файла в `rom/` запусти
`python tools/computer/update_rom_list.py`. Проверить компьютер без запуска игры:
`python tools/computer/run_test.py путь/к/cobalt.jar` (то же самое автоматически делает GitHub при каждом push).

**Главная идея.** Внутри предмета хранится только «чертёж»: номера выбранных вариантов для каждого параметра.
Всё остальное — характеристики, уровень, стоимость, цвета, вариант 3D-модели — вычисляет спецификация
(`hardware/spec/*Spec.java`). Хочешь новый параметр или поменять баланс — правишь спецификацию.

**Как считается производительность.** `hardware/Perf.java` — формулы для отдельных деталей,
`hardware/SystemModel.java` — оценка всей сборки. Коротко:

| Деталь | Формула |
|---|---|
| Процессор | частота × IPC (растёт с техпроцессом и кэшем) × ядра (с потерями на совместную работу) |
| Память | скорость (МТ/с) × 8 байт × задействованные каналы; процессору нужно ≈ 0,4 ГБ/с на млрд оп/с, кэш снижает потребность |
| Видеокарта | шейдеры × частота × 2 = FLOPS; шина = чипы × 32 бита; скорость памяти GDDR5/6/6X/7 = 8/16/21/28 Гбит/с |
| Нагрев | если охлаждение отводит меньше, чем греет чип, частота = ∛(отвод / нагрев), но не ниже 25% |
| Накопители | загрузка = 3 с + 1500 МБ подряд + 4000 случайных чтений |
| Блок питания | из розетки = нагрузка / КПД |

Опорные значения заводских деталей (`STOCK_*` в `Perf.java`) проверяет `tools/spectest/run.py` — если поменял
формулы или пресеты, тест подскажет, какие числа обновить. Там же печатаются примеры неудачных сборок.

**Как работают модели.** У каждой детали есть до трёх «измерений вида» (`visual(v, 0..2)` в спецификации:
тип крышки, число слотов, длина видеокарты...). По ним JSON-модель выбирает нужный вариант геометрии.
Цвета накладываются слоями: `tintindex` 1 — основной цвет, 2 — подсветка/наклейка, 3 — текстолит.

**Положение деталей в корпусе** заложено прямо в 3D-модели (координаты корпуса, 1 пиксель ≈ 2,8 см).
`client/PcCaseRenderer.java` ставит центр модели в опорную точку корпуса и сдвигает на шаг слота.

## Модели и текстуры: генераторы (`tools/`)

JSON-модели (их 381) и текстуры **не пишутся вручную** — их генерируют Python-скрипты. Нужны Python 3
и библиотеки `pillow` и `numpy` (`pip install pillow numpy`). Все команды — из корня репозитория.

| Что сделать | Команда |
|---|---|
| Проверить спецификации и обновить список вариантов моделей | `python tools/spectest/run.py` |
| Перегенерировать все модели и текстуры деталей | `python tools/assetgen/build_v6.py . tools/assetgen/spec_dump.json` |
| Перегенерировать переводы | `python tools/assetgen/build_lang6.py .` |
| Текстуры корпуса | `python tools/assetgen/build_blocks.py src/main/resources/assets/minepc/textures/block` |
| Проверить, что детали в корпусе не пересекаются | `python tools/assetgen/collide6.py . tools/assetgen/spec_dump.json` |
| Модели и текстуры монитора, клавиатуры, дисковода, дискеты, флешки | `python tools/assetgen/build_devices.py` |
| Корпуса-варианты из воксельных эскизов (`tools/assetgen/looks`) | `python tools/assetgen/cases.py` |
| Мониторы новых видов, навесная клавиатура, стойка | `python tools/assetgen/monitors.py` (запускается и из `build_devices.py`) |
| Коммутаторы, текстуры кабеля, рецепты сети | `python tools/assetgen/lan.py` |
| Силуэты деталей для пустых слотов окна корпуса | `python tools/assetgen/ghosts.py` |
| Нарисовать корпус со сборкой (без запуска игры) | `python tools/assetgen/preview3d.py . preview.png tools/assetgen/example_build.json` |

Где что лежит:
- `models6.py` — **геометрия всех деталей** (функции `cpu`, `gpu`, `ram`...), в координатах корпуса
- `materials5.py`, `materials.py`, `items.py` — процедурные текстуры
- `build_v6.py` — собирает всё вместе, ракурсы иконок (`hero`), сборочный стол, рецепты
- `build_lang6.py` — **все переводы** (ru/en). Новые ключи добавлять туда, а не в JSON

**Порядок при изменении спецификации:** поменял `*Spec.java` → `tools/spectest/run.py` → `build_v6.py`
→ `collide6.py` → `build_lang6.py` (если добавились параметры).

## Совместная работа

- Перед началом работы: `git pull`
- Мелкие правки можно сразу в `main`, крупные — в отдельной ветке и через Pull Request
- После `git push` GitHub сам собирает мод (вкладка **Actions**): зелёная галочка — компилируется, красный
  крестик — открыть и посмотреть ошибку
- Не коммить папки `build/`, `run/`, `.idea/` — они уже в `.gitignore`
