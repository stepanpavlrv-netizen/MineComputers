# MineComputers

Мод для **Minecraft 1.21.1 (NeoForge)** про настоящие компьютеры: детали проектируются на сборочном столе,
собираются в системном блоке, а сквозь стеклянную стенку видно, что установлено внутри.

- **Сборочный стол.** Конструктор комплектующих: ядра и техпроцесс процессора, чипы памяти, плата и охлаждение
  видеокарты, чипсет материнской платы, цвета текстолита, радиаторов и подсветки, гравировка на крышке
  процессора. Характеристики (тепловыделение, объём, отвод тепла) вычисляются из выбранных параметров
- **8 видов деталей:** материнская плата, процессор, кулер, оперативная память, видеокарта, блок питания,
  жёсткий диск, SSD. У каждой есть 5 заводских уровней
- **Системный блок** со стеклянной боковиной: детали стоят внутри как в реальном ПК (3D-модели в реальных пропорциях)
- **Совместимость:** сокеты, чипсет ограничивает уровень процессора, слоты памяти, M.2 и SATA, каналы памяти,
  мощность блока питания, охлаждение процессора и видеокарты

> Статус: ранняя разработка. Сами компьютеры пока не «включаются» — это следующий большой этап.

## Как запустить у себя

1. **Java 21** — [Temurin 21 (LTS)](https://adoptium.net/), при установке включить «Set JAVA_HOME» и «Add to PATH».
   Проверка: `java -version` в командной строке должна показать 21
2. **IntelliJ IDEA** — [jetbrains.com/idea](https://www.jetbrains.com/idea/download/), бесплатной версии достаточно.
   Полезен плагин **Minecraft Development** (Settings → Plugins)
3. Склонировать репозиторий **в папку без русских букв и пробелов**, например `D:\Mods\MineComputers`
4. В IntelliJ: **File → Open** → папка репозитория → **Trust Project**. Первая загрузка (Gradle sync) занимает
   5–20 минут: скачивается сам Minecraft
5. Запуск игры: в терминале IntelliJ (`Alt+F12`)
   ```
   .\gradlew runClient
   ```
   или вкладка **Gradle** (слон справа) → **Tasks → mod development → runClient**

В игре всё лежит во вкладке творческого режима **MineComputers**.

### Если что-то не запускается

- **`Failed to run Gradle Worker Daemon`** — почти всегда русские буквы в имени пользователя Windows.
  Создай папку `D:\gradle-home` и переменную среды пользователя `GRADLE_USER_HOME = D:\gradle-home`,
  перезапусти IntelliJ, выполни `.\gradlew --stop`, затем снова `.\gradlew runClient`
- **Ошибка 504 при скачивании Gradle** — скачай `gradle-9.2.1-bin.zip` через браузер
  (`https://services.gradle.org/distributions/gradle-9.2.1-bin.zip`), положи, например, в `D:\Mods\`
  и в `gradle/wrapper/gradle-wrapper.properties` поменяй строку на
  `distributionUrl=file\:///D:/Mods/gradle-9.2.1-bin.zip`.
  Чтобы git не пытался отправить это изменение в репозиторий:
  ```
  git update-index --skip-worktree gradle/wrapper/gradle-wrapper.properties
  ```
- **`Unknown command-line option '-b'`** — запускался сам файл `build.gradle`. Запускай задачу `runClient`, как выше
- Если в меню **New** нет пунктов **Package** и **Java Class** — открыта не та папка (нужна та, где лежит
  `build.gradle`) или ещё не закончилась загрузка Gradle

## Как устроен код

```
src/main/java/com/strikerr212/minepc/
├── MineComputers.java          главный класс, регистрирует всё остальное
├── hardware/
│   ├── spec/                   ★ СЕРДЦЕ МОДА: параметры и расчёты деталей
│   │   ├── PartSpec.java         базовый класс спецификации (уровень, стоимость, вид)
│   │   ├── CpuSpec.java ...      по классу на каждый вид детали
│   │   ├── Param.java            один настраиваемый параметр
│   │   ├── Palette.java          палитры цветов
│   │   ├── PartDesign.java       "чертёж", который хранится внутри предмета
│   │   └── Specs.java            все спецификации в одном месте
│   ├── HardwarePresets.java    заводские детали 5 уровней + примеры самосборных
│   └── *Data.java              вычисленные характеристики (паспорт детали)
├── item/                       предметы-детали (тонкая обёртка над спецификацией)
├── block/                      системный блок и сборочный стол
├── menu/AssemblyMenu.java      серверная логика сборочного стола
├── network/                    пакет с надписью (клиент → сервер)
├── client/                     всё, что только рисует: экран стола, рендер деталей в корпусе, цвета
└── registry/                   регистрация блоков, предметов, меню, вкладки
```

**Главная идея.** Внутри предмета хранится только «чертёж»: номера выбранных вариантов для каждого параметра.
Всё остальное — характеристики, уровень, стоимость, цвета, вариант 3D-модели — вычисляет спецификация
(`hardware/spec/*Spec.java`). Хочешь новый параметр или поменять баланс — правишь спецификацию.

**Как работают модели.** У каждой детали есть до трёх «измерений вида» (`visual(v, 0..2)` в спецификации:
тип крышки, число слотов, длина видеокарты...). По ним JSON-модель выбирает нужный вариант геометрии.
Цвета накладываются слоями: `tintindex` 1 — основной цвет, 2 — подсветка/наклейка, 3 — текстолит.

**Положение деталей в корпусе** заложено прямо в 3D-модели (координаты корпуса, 1 пиксель ≈ 2,8 см).
`client/PcCaseRenderer.java` ставит центр модели в опорную точку корпуса и сдвигает на шаг слота.

## Модели и текстуры: генераторы (`tools/`)

JSON-модели (их 381) и текстуры **не пишутся вручную** — их генерируют Python-скрипты. Нужны Python 3
и библиотеки `pillow` и `numpy` (`pip install pillow numpy`). Все команды — из корня репозитория.

| Что сделать | Команда |
|---|---|
| Проверить спецификации и обновить список вариантов моделей | `python tools/spectest/run.py` |
| Перегенерировать все модели и текстуры деталей | `python tools/assetgen/build_v6.py . tools/assetgen/spec_dump.json` |
| Перегенерировать переводы | `python tools/assetgen/build_lang6.py .` |
| Текстуры корпуса | `python tools/assetgen/build_blocks.py src/main/resources/assets/minepc/textures/block` |
| Проверить, что детали в корпусе не пересекаются | `python tools/assetgen/collide6.py . tools/assetgen/spec_dump.json` |
| Нарисовать корпус со сборкой (без запуска игры) | `python tools/assetgen/preview3d.py . preview.png tools/assetgen/example_build.json` |

Где что лежит:
- `models6.py` — **геометрия всех деталей** (функции `cpu`, `gpu`, `ram`...), в координатах корпуса
- `materials5.py`, `materials.py`, `items.py` — процедурные текстуры
- `build_v6.py` — собирает всё вместе, ракурсы иконок (`hero`), сборочный стол, рецепты
- `build_lang6.py` — **все переводы** (ru/en). Новые ключи добавлять туда, а не в JSON

**Порядок при изменении спецификации:** поменял `*Spec.java` → `tools/spectest/run.py` → `build_v6.py`
→ `collide6.py` → `build_lang6.py` (если добавились параметры).

## Совместная работа

- Перед началом работы: `git pull`
- Мелкие правки можно сразу в `main`, крупные — в отдельной ветке и через Pull Request
- После `git push` GitHub сам собирает мод (вкладка **Actions**): зелёная галочка — компилируется, красный
  крестик — открыть и посмотреть ошибку
- Не коммить папки `build/`, `run/`, `.idea/` — они уже в `.gitignore`
